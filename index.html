🎯 Project Overview

Scholar's Digital Library is a full-stack desktop application combining a modern Tkinter GUI with a Flask REST API backend. The system demonstrates professional software engineering with separation of concerns, RESTful architecture, persistent storage, and comprehensive testing.

🏗️ System Architecture

Three-Tier Design:

  • Frontend: Tkinter desktop GUI for user interaction
  • Backend: Flask REST API with 7 HTTP endpoints
  • Storage: JSON-based persistence with UUID management

The GUI communicates via HTTP with intelligent local fallback if the server is unavailable.

⚙️ Backend Implementation

Flask REST API (server.py) with 7 endpoints:

  • GET /media → List all items or filter by category
  • GET /media/search?name=X → Exact name search
  • GET /media/<id> → Get specific item
  • POST /media → Create new item
  • PUT /media/<id> → Update existing item
  • DELETE /media/<id> → Remove item

🖥️ Frontend Features

Modern Tkinter interface (main.py) with:

  • Sortable table with alternating row colors
  • Category filtering (All, Book, Film, Magazine)
  • Search functionality for titles and authors
  • Add, Edit, Delete, and View Details dialogs
  • Status bar showing collection statistics
  • Right-click context menu for quick actions

💾 Data Storage

Centralized storage module (storage.py) features:

  • JSON file format in media.json
  • Automatic UUID generation and management
  • Thread-safe file operations
  • Functions: list, search, create, update, delete

🧪 Testing

Comprehensive pytest suite with 3 test functions:

  • test_storage_add_and_delete - Storage layer validation
  • test_server_endpoints - Flask API testing
  • test_storage_update_and_filters - Category and search testing

Run with: pytest -q

🚀 Getting Started

  1. Activate Environment: .\.venv\Scripts\Activate.ps1
  2. Install Dependencies: pip install -r requirements.txt (if needed)
  3. Start Backend Server: python server.py (runs on http://127.0.0.1:5000)
  4. Launch GUI: Open a new terminal and run python main.py
  5. Run Tests: pytest -q to validate all functionality

Note: The GUI works independently even if the server isn't running, thanks to the intelligent HTTP-first with local fallback architecture.
