🎯 Project Overview

Scholar's Digital Library is a comprehensive advanced programming project that implements a full-stack desktop application for managing multimedia collections. The system combines a modern Tkinter graphical user interface with a powerful Flask REST API backend, demonstrating professional software engineering principles including separation of concerns, RESTful architecture, persistent data storage, and comprehensive testing.

This project showcases mastery of Python programming, GUI development, web service architecture, data persistence, testing methodologies, and documentation practices—all essential skills for professional software development.

🏗️ System Architecture

Three-Tier Architecture:

  • Presentation Layer (Frontend): Tkinter desktop application providing an intuitive graphical interface for end users to interact with the library system.
  • Application Layer (Backend): Flask REST API server handling all business logic, request processing, and data validation through standardized HTTP endpoints.
  • Data Layer (Storage): Centralized JSON-based persistence module with thread-safe file operations and UUID-based record management.

Design Philosophy: The architecture follows HTTP-first communication with intelligent local fallback, ensuring maximum reliability. The GUI attempts to communicate with the Flask backend via HTTP requests; if the server is unavailable, it seamlessly falls back to direct local JSON file operations.

⚙️ Backend Implementation (Flask REST API)

The Flask backend (server.py) implements a complete RESTful API with 7 HTTP endpoints covering all CRUD operations:

  • GET /media → Returns all media items in JSON format
  • GET /media?category=X → Filters and returns items by category (Book, Film, or Magazine)
  • GET /media/search?name=X → Performs exact-match search by name; returns 404 if not found
  • GET /media/<id> → Retrieves a specific item by its UUID
  • POST /media → Creates a new media item with validation; returns 201 on success with created item
  • PUT /media/<id> → Updates an existing item while preserving its UUID
  • DELETE /media/<id> → Removes an item; returns 404 if not found, 200 on success

Technical Features: The backend uses Flask's application factory pattern (create_app()), proper HTTP status codes, JSON response formatting, and integrates seamlessly with the centralized storage module for all data operations.

🖥️ Frontend Implementation (Tkinter GUI)

The Tkinter desktop application (main.py) provides a professional-grade user interface with the following features:

  • Main Table View: Displays all library items in a sortable table with columns for Serial Number, Name, Author, Date, and Category. Features alternating row colors for enhanced readability.
  • Category Filter: Dropdown combobox allowing users to filter by "All", "Book", "Film", or "Magazine" categories with instant results.
  • Exact-Match Search: Real-time search functionality that finds items by exact name matching, meeting project requirements for precise querying.
  • CRUD Operations:
    • Load: Fetches all items via HTTP GET request with local fallback
    • New: Opens dialog for adding items via HTTP POST
    • Edit: Double-click or "Sort by Date" to edit; preserves UUID and updates via HTTP PUT
    • Delete: "Erase" button removes selected item via HTTP DELETE
  • Serial Numbering: Automatically assigns sequential numbers (1, 2, 3...) to displayed items for easy reference.
  • UUID Management: All records identified by stable UUIDs stored as tree item IDs, preventing data mismatches during edits.

User Experience: The interface includes clear button labels, instant visual feedback, error handling dialogs, and responsive layout that adapts to window resizing.

💾 Data Persistence & Storage

The centralized storage module (storage.py) handles all data persistence with robust reliability:

  • JSON File Format: All data stored in media.json with human-readable structure for easy debugging and manual editing if needed.
  • UUID Management: Automatic UUID generation for new items; existing UUIDs preserved during updates to maintain referential integrity.
  • Thread Safety: Threading locks prevent race conditions during concurrent file write operations.
  • Core Functions:
    • load_data() - Loads JSON and auto-injects missing UUIDs
    • save_data() - Thread-locked file writes
    • list_all() - Returns all records
    • list_by_category(category) - Filters by Book/Film/Magazine
    • search_by_name_exact(name) - Exact string matching
    • get_by_id(item_id) - UUID-based retrieval
    • create_item(data) - Adds with UUID assignment
    • update_item(item_id, data) - Updates while preserving ID
    • delete_item(item_id) - Removes by UUID

🚀 Getting Started

  1. Activate Environment: .\.venv\Scripts\Activate.ps1
  2. Install Dependencies: pip install -r requirements.txt (if needed)
  3. Start Backend Server: python server.py (runs on http://127.0.0.1:5000)
  4. Launch GUI: Open a new terminal and run python main.py
  5. Run Tests: pytest -q to validate all functionality

Note: The GUI works independently even if the server isn't running, thanks to the intelligent HTTP-first with local fallback architecture.
